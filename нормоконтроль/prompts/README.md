# Промты LLM-агентов модуля «Нормоконтроль»

Статус: каркас (Этап 1). Сами системные промты пишутся на Этапе 3 — здесь зафиксировано,
какие утверждённые приёмы из `decisions/prompt-techniques-review.md` (согласовано 24.08.2026)
в какой промт входят. Каждый будущий файл промта обязан в шапке перечислять номера П/А,
которые он реализует, — трассировка «приём → промт» проверяется при ревью.

## Общие требования ко всем промтам (из согласованного обзора)

- Семиблочная структура: роль / контекст / вход / задача / формат / ограничения / самопроверка (П23, П22).
- Манифест входов: промт явно перечисляет, какие документы приложены и что откуда брать (П30, П31).
- Запрет итогового вердикта уровня документа; только пофактные находки со статусами (П41).
- Четырёхстатусная модель результата: подтверждено / требует проверки / не соответствует / нет данных; «нет данных ≠ соответствует» (П42).
- Обязательные раздельные поля source.ntd и clause + confidence + дословные цитаты обоих концов (П43, П44).
- Блок типовых сбоев и контрмер: не додумывать, пробелы показывать явно (П47); финальный шаг self-critique «перечисли свои дописки» (П14, П13).
- Шифры НТД в контекст попадают только сверенными по реестру; редакция резолвится на момент прогона (П46, П53).
- Один промт = одна узкая проверка (П25, П26); параметры объекта — во внешнем блоке контекста (П53, А10).
- Стабильный системный промт + фиксированные параметры (t=0, seed) — консенсус прогонов в проде не используется (А16-A).
