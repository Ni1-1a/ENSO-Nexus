# Маппинг: поля формы заключения ↔ модель данных модуля «Нормоконтроль»

Источник структуры формы: `templates/conclusion.md` (эталон 1:1 по «Форма нормоконтроль.docx», разбор — extracts/G-форма.md от 2026-08-24).
Сущности модели: `Project`, `Section`, `SectionVersion`, `Finding`, `Report`.
Открытые вопросы здесь не решаются — помечены «→ decisions/open-questions.md».

## 2. Чек-таблицы: 15 показателей ↔ группы правил каталога

Логика галочки (единая для всех 15 показателей):

- **«Да»** = по группе правил, закрывающей показатель, нет открытых `Finding` для проверяемой `SectionVersion`;
- **«Нет»** = есть хотя бы один открытый `Finding` группы;
- **«Примечания»** = автосводка по группе (количество замечаний, коды, при необходимости краткий перечень). Severity в форме источника отсутствует — как отражать её в сводке, → decisions/open-questions.md.

Хранение: агрегат вычисляется из `Finding` на момент формирования `Report` (снимок фиксируется в Report), сами галочки отдельно не редактируются.

## 3. Итоговые блоки

| Поле формы | Сущность.атрибут | Откуда берётся значение | Примечание |
|---|---|---|---|
| Замечания ({{findings}}) | Report → список Finding | открытые Finding проверяемой SectionVersion: wording (текст + ссылка на НТД), лист/место, код классификатора | Порядок нумерации замечаний формой не задан — → decisions/open-questions.md |
| Рекомендации ({{recommendations}}) | Finding severity=remark (?) | предложения, не обязательные к исправлению (по ГОСТ 21.002-2014 п. 7.4 — учитываются при согласии разработчика) | Маппинг «Рекомендации = severity remark» НЕ утверждён — → decisions/open-questions.md |
| Документация соответствует требованиям ({{verdict_compliant}}) | Report.verdict_compliant | решение нормоконтролёра | Два независимых флага (не один verdict). Логика автоподсказки (все обязательные Finding закрыты?) — → decisions/open-questions.md |
| Документация допущена к выпуску ({{verdict_approved}}) | Report.verdict_approved | решение нормоконтролёра | см. выше |
| Подпись нормоконтролёра ({{signature}}) | Report.signed_by | подписант заключения | В форме источника подпись только одна (нормоконтролёр) |
| Дата ({{sign_date}}) | Report.signed_at | дата подписания | В источнике на месте даты символ «☒» |

## 4. Открытые вопросы маппинга (→ decisions/open-questions.md)

Не решать в шаблонах — только фиксация:

1. Нумерация блоков формы: воспроизводить сбитую («1», «1», 2–6) или чинить при рендере (также в decisions/conflicts.md).
2. Пункт «Оформление листов по ГОСТ Р 21.110-2013»: опечатка (д.б. ГОСТ Р 21.101-2020) или проверка спецификаций (также в decisions/conflicts.md).
3. «Рекомендации» = Finding с severity=remark — подтвердить или завести отдельный тип записи.
4. Стадия (П/Р): атрибут Project или SectionVersion.
5. Организация-исполнитель: атрибут Project или Section (случай субподряда).
6. Наименование проекта: включать ли заказчика (Project.customer) в выводимую строку, как в предзаполнении источника.
7. Дата проверки: момент прогона правил или момент формирования заключения.
8. Порядок нумерации замечаний в {{findings}} (по листам, по коду, по severity) — формой не задан.
9. Автозаполнение вердиктов из состояния Finding: подсказка или ручной выбор без подсказки.
10. Severity замечаний: в форме источника категорий нет — как (и надо ли) показывать её в графе «Примечания» и в списке замечаний.
11. Трактовка галочки показателя «Наличие дублирования/несостыковок» (инвертированная семантика «Да/Нет»).
