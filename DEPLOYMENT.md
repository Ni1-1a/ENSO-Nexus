# Деплой — ENSO Nexus Pilot 1 Web

## Вариант A (текущий): свой компьютер + Cloudflare quick tunnel

Работает сейчас, без аккаунтов и подписок: сервер приложения крутится на этом Mac (AI — локальная модель в LM Studio), публичный HTTPS даёт бесплатный quick-туннель Cloudflare.

```bash
cd "ENSO-Nexus/Pilot 1/Web"
bash scripts/serve-public.sh        # старт: печатает публичный URL (и в logs/public-url.txt)
bash scripts/serve-public.sh stop   # остановка
```

Скрипт: запускает `npm start` под `caffeinate -i` (Mac не уснёт, пока сервер работает; крышку не закрывать), поднимает `cloudflared tunnel --url http://localhost:3000` и сохраняет URL.

Ограничения этого варианта:
- URL вида `https://<случайные-слова>.trycloudflare.com` **меняется при каждом перезапуске** туннеля/компьютера — новую ссылку смотреть в `logs/public-url.txt`;
- сервис доступен, только пока компьютер включён и в сети;
- LM Studio должен быть запущен с загруженной моделью (`qwen/qwen3-vl-30b`), иначе приложение честно перейдёт в демо-режим.

### Постоянная ссылка (работает сейчас, домен не нужен)

**https://ni1-1a.github.io/ENSO-Nexus/** — постоянная страница-вход на GitHub Pages (ветка `gh-pages` этого репозитория). Она мгновенно перенаправляет на текущий адрес туннеля и **обновляется автоматически**: `scripts/serve-public.sh` после получения нового quick-URL вызывает `scripts/update-public-link.sh`, который коммитит новую страницу-редирект в `gh-pages` и пушит (GitHub Pages пересобирается за ~10–30 с). Эту ссылку можно раздавать пользователям — она не меняется.

### Постоянный адрес на своём домене (опция на будущее)

Если появится собственный домен: добавить его в Cloudflare (бесплатный план), выполнить `cloudflared tunnel login` (авторизация в браузере), затем `cloudflared tunnel create pilot1` + `cloudflared tunnel route dns pilot1 pilot1.<домен>` + локальный config с ingress `http://localhost:3000` — получится адрес вида `https://pilot1.<домен>` без страницы-редиректа. Настроенные MCP-серверы Cloudflare (`.mcp.json` в рабочей директории) позволяют сделать это и через API после OAuth-авторизации.

## Вариант B: облачная платформа

**Render.com (free tier)** — рекомендованный вариант: один web-сервис обслуживает и API, и статику, HTTPS из коробки, деплой из git-репозитория по готовому [render.yaml](render.yaml). Альтернативы с тем же кодом: Railway, Fly.io, любой Docker-хостинг (готов [Dockerfile](Dockerfile)).

> Требование платформе: постоянный Node-процесс (Node ≥ 22.5). Приложение не serverless-совместимо без доработки (SQLite + фоновые задачи).

## Порядок деплоя (Render)

1. Запушить папку `Web/` на GitHub. Локальный git-репозиторий уже создан (коммит готов). Через **GitHub Desktop**: File → Add Local Repository → выбрать `ENSO-Nexus/Pilot 1/Web` → Push (репозиторий `Ni1-1a/ENSO-Nexus` уже создан на GitHub; в диалоге публикации выбрать его или нажать Publish).
   `.gitignore` уже исключает `node_modules/`, `data/`, `logs/`, `.env` — секреты и данные пользователей в git не попадают. **Не публикуйте всю папку ENSO-Nexus целиком**: в ней есть закрытые документы и файлы с паролями (например, `n8n-Docker/.nc_pg_password`).
2. В [dashboard.render.com](https://dashboard.render.com): **New → Blueprint** → указать репозиторий. Render прочитает `render.yaml` и создаст сервис `enso-nexus-pilot1`.
   (Либо **New → Web Service** вручную: Build `npm ci`, Start `npm start`, Health check `/api/health`.)
3. В настройках сервиса → **Environment** добавить секрет:
   - `ANTHROPIC_API_KEY` = ключ, созданный в [console.anthropic.com](https://console.anthropic.com) → API Keys.
   Остальные переменные необязательны (см. ниже).
4. Дождаться первого деплоя → сервис получает адрес `https://<name>.onrender.com`.
5. Проверить: открыть сайт, `GET /api/health` должен вернуть `"aiMode": "live"`.

## Переменные окружения на платформе

| Переменная | Обязательна | Значение |
|---|---|---|
| `ANTHROPIC_API_KEY` | да (для боевого режима) | секрет из консоли Anthropic; задаётся только в дашборде платформы |
| `ANTHROPIC_MODEL` | нет | по умолчанию `claude-opus-5` |
| `DATA_DIR` | нет | на free-тарифе не задавать (данные в каталоге приложения); с persistent-диском — `/var/data` |
| `SESSION_TTL_HOURS` | нет | 72 |
| Остальные лимиты | нет | см. `.env.example` |

## Настройка frontend / backend / хранилища

- **Frontend** отдельной настройки не требует: статика из `public/` отдаётся тем же сервисом, обращается к API по относительным путям (`/api/...`) — значит, работает на любом домене без правок и не ссылается на localhost.
- **Backend** конфигурируется только переменными окружения.
- **Хранилище** — SQLite + файлы в `DATA_DIR`.
  - Free-тариф Render: диск эфемерный — при повторном деплое/рестарте сессии пользователей теряются. Для пилота это допустимо (сессии и так живут ≤ 72 ч), ограничение честно указано ниже.
  - Платный тариф: подключить Persistent Disk (1 ГБ), смонтировать в `/var/data`, задать `DATA_DIR=/var/data` (закомментированный блок есть в `render.yaml`).

## Ограничения бесплатного тарифа Render

- Сервис засыпает после ~15 минут без трафика; первый запрос будит его за 30–60 с.
- Нет persistent-диска → данные сессий не переживают redeploy/restart.
- 750 часов инстанса в месяц, ограниченные CPU/RAM (хватает для пилота).

## Повторный деплой

Каждый `git push` в подключённую ветку автоматически пересобирает и перезапускает сервис (`npm ci` → `npm start`). Переменные окружения сохраняются. Откат — через **Rollback** в дашборде Render.

## Чек-лист проверки после деплоя

1. Сайт открывается по HTTPS.
2. `GET /api/health` → `{"ok":true,"aiMode":"live",...}` (если `mock` — ключ не подхватился).
3. Создание сессии, загрузка файла, запуск обработки, ответ на вопрос, скачивание результата и ZIP.
4. Обновление страницы восстанавливает сессию.
5. Вторая вкладка в приватном окне получает независимую сессию.

## Страницы ошибок Cloudflare

Когда платформа недоступна, гость видит страницу, которую рисует край Cloudflare,
а не наш сервер. Отказа два, и они разные:

| Что выключено | Ошибка | Класс страницы |
|---|---|---|
| Mac включён, `cloudflared` работает, Node на :3000 не поднят | Bad gateway, 502 | **500 class errors** |
| Mac выключен — здоровых коннекторов нет | Error 1033, отдаётся со статусом 530 | **1000 class errors** |

Обе подменяются только через настройки зоны — из репозитория это сделать нельзя.
Страницы в оформлении платформы уже свёрстаны и опубликованы на GitHub Pages
(ветка `gh-pages`), потому что они обязаны быть доступны, когда домашний Mac выключен:

- <https://ni1-1a.github.io/ENSO-Nexus/error-5xx.html> — класс «500 class errors»
- <https://ni1-1a.github.io/ENSO-Nexus/error-1033.html> — класс «1000 class errors»
- <https://ni1-1a.github.io/ENSO-Nexus/> — приёмная: ждёт платформу и открывает её сама

Исходники — `public/error-pages/`. При правке скопировать в ветку `gh-pages`
(`error-5xx.html`, `error-1033.html`, `index.html`) и нажать в панели
«Fetch custom page again» — Cloudflare хранит СНИМОК страницы, а не ссылку.

### Что нажать в панели Cloudflare

1. Панель → домен `enso-nexus.ru` → **Rules → Custom Errors** (в старых версиях
   раздел называется **Custom Pages**).
2. **500 class errors** → *Custom Pages* → указать
   `https://ni1-1a.github.io/ENSO-Nexus/error-5xx.html` → **Publish**.
3. **1000 class errors** → указать
   `https://ni1-1a.github.io/ENSO-Nexus/error-1033.html` → **Publish**.

Требования Cloudflare, которые в этих файлах уже соблюдены: адрес отдаёт 200 по HTTPS,
есть явные `<head>` и `</head>`, присутствует обязательный токен своего класса
(`::CLOUDFLARE_ERROR_500S_BOX::` / `::CLOUDFLARE_ERROR_1000S_BOX::`), все стили и скрипты
инлайновые, размер намного меньше потолка в 1,5 МБ.

Если тариф зоны не даёт подменять страницы ошибок, приёмная на GitHub Pages
остаётся рабочим запасным входом: она живёт независимо от Mac и сама открывает
платформу, как только та поднимется.

### Ошибка внутри самой платформы

`public/error-pages/app-404.html` отдаётся сервером, когда браузер запросил
несуществующий адрес живой платформы. Публиковать её никуда не надо — она
раздаётся тем же процессом. Запросы к `/api/` по-прежнему получают JSON:
интерфейс разбирает ошибки по полю `error`, и HTML вместо него сломал бы разбор.

## Мост AutoCAD: разрешение macOS

DWG строит сам AutoCAD; сервер отдаёт ему задание через папку обмена и вводит
команду `CLAUDE-PUMP` через AppleScript. macOS считает это управлением чужим
окном и требует разрешения:

**Системные настройки → Конфиденциальность и безопасность → Универсальный доступ**
→ включить программу, из которой запущен сервер (Терминал или Claude Code).

Без разрешения запрос уходит в папку обмена и остаётся без ответа; в примечаниях
к выгрузке платформа так и пишет — «macOS не разрешает вводить команды в чужое
окно» — и собирает DWG конвертером LibreDWG. Конвертерный файл после перехода
DXF на CP1251 сохраняет кириллические имена слоёв, штриховки и их углы, так что
он рабочий; но полноценный путь — через AutoCAD.

Второй вариант — `ACAD_TRIGGER=manual` в `.env`: тогда команду `CLAUDE-PUMP`
в AutoCAD вводит человек, и разрешение не нужно.

### Как на самом деле получается DWG

Разрешения мало: автоввод команды спотыкается ещё о две вещи — русскую
раскладку (macOS печатает в AutoCAD не те буквы) и закрытую по умолчанию
командную строку AutoCAD for Mac. Поэтому рабочий порядок такой:

1. Файлы моста лежат в `~/Library/Application Support/Autodesk/AutoCAD 2027/R26.0/roaming/@en@/Support/`
   — именно эту папку AutoCAD просматривает. Там же `acaddoc.lsp`, который
   поднимает мост и расширение при открытии каждого чертежа.
   Исходники — `scripts/acaddoc.lsp`, `scripts/enso-acad-export.lsp`.
2. Перед выгрузкой один раз ввести в командной строке AutoCAD (⌘3, если её не видно):

   ```
   CLAUDE-SERVE
   ```

   Мост начнёт читать папку обмена сам — клавиатура больше не нужна.
   AutoCAD на это время перестаёт отвечать на мышь, это нормально.
3. Запустить выгрузку в платформе. Она займёт секунды, после чего платформа
   **сама остановит режим сервера** (флаг `STOP` в папке обмена).

Проверить, что мост поднялся: команда `CLAUDE-STATUS` должна ответить
`[claude-mcp] мост загружен`. Расширение Enso-nexus добавляет ему две команды —
`export_dwg` (выгрузка через `-WBLOCK`) и `create_hatch_holes` (кольцевые зоны
с вырезом). Без расширения выгрузка не падает: платформа откатывается на
штатную заливку и пишет об этом в примечаниях к результату.
