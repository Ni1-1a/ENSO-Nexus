### Что канал предлагает, а платформа уже решила иначе

- Сведение 2–3 прогонов (3/3, 2/3, 1/3) — в проде НЕ используется: решение
  А16-A (стабильный промпт, t=0, seed). Промпты сведения лежат в библиотеке
  для ручной работы.
- Оценка актуальности редакций моделью (протокол Б.2) — запрещена нашим же
  правилом «редакция резолвится кодом на момент прогона» (П46/П53); поздний
  материал канала (пост 349) сам пришёл к этому же.

## Решения владельца (27.08.2026) и их реализация (28.08.2026)

1. Автоподбор промпта при загрузке документа — ✅ модуль «Проверка документа»
   (`/doccheck.html`): маркеры кода → модель → выбор человека сильнее; прогон
   стартует сам при загрузке; карта «тип → промпт» — `server/services/doclib.js`
   (ROUTES), покрыта тестом.
2. Замена оборудования A→B — ✅ экран «Замена A→B» той же страницы: протокол
   по схеме xlsx-канала, 4 статуса, вердикт запрещён, решение по строке ставит
   инженер, экспорт xlsx.
3. Конвейер актов АОСР — ✅ вкладка «Акты (АОСР)» (`/akty.html`): реестр ×
   шаблон → zip черновиков + отчёт пропусков; сверка дат акт↔журнал. Без модели.
4. Входной контроль ГГЭ — ✅ вкладка «Контроль ГГЭ» (`/gge.html`): имена по
   783/пр, текстовый слой, посимвольная сверка реквизитов, развилки по датам.
   Без модели.
5. Мониторинг нормативной базы — ✅ первая часть: перечень ссылок на НТД со
   сверкой по реестру (208 записей) строится кодом в КАЖДОМ прогоне «Проверки
   документа» (`doccheck/ntd-refs.js`). Сводка изменений и diff редакций —
   после подключения Техэксперта (Этап 3 нормоконтроля).
6. Дополнение обзора техник — ✅ приёмы Д1–Д10 внесены в
   `нормоконтроль/decisions/prompt-techniques-review.md`, разнесены по агентам
   в `нормоконтроль/prompts/README.md`; Д1/Д4/Д5/Д6/Д7 уже работают в коде
   новых модулей.
