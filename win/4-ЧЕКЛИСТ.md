# 4. Приёмка: чем доказывается, что перенос состоялся

Правило проекта: «сделано» — это прогон на настоящих исходных данных и на живых
моделях, а не «код поправлен». Ниже — что запустить и что должно получиться.
К каждому пункту в отчёте прикладывается команда и её вывод.

Исходные данные для проверки: `ENSO-Nexus/Pilot 1/Исходные данные/` —
`ГПЗУ.pdf` (скан на 17 страниц), `МСК-47_Горбунки.dwg`, техническое задание.

---

## 1. Окружение

```powershell
node -v                                        # v24 или новее
node -e "require('node:sqlite'); console.log('sqlite ok')"
git --version
pwsh -v
cloudflared --version
pdfinfo -v ; pdftoppm -v                       # poppler
dwg2dxf --version ; dxf2dwg --version          # LibreDWG
lms --version                                  # CLI LM Studio
```

Пусто или «не найдено» хотя бы в одной строке — записать, чего нет, и что из-за
этого не работает. Молча пропускать нельзя: каждый из этих пунктов отключает
кусок платформы тихо.

## 2. Зависимости и запуск

```powershell
npm ci
npx playwright install chromium
npm test                                       # если шаблон не раскрылся — node --test tests\
```

Тестов на маке было **312**. Меньше — разобраться, каких именно и почему;
упавшие тесты разобрать по одному, а не списком.

```powershell
pwsh -File win\scripts\start.ps1
curl.exe -s http://127.0.0.1:3000/api/health
```

Ожидается `{"ok":true, ... "aiMode":"local"}` (или `"live"`). `"mock"` —
это заглушка: ни ключа, ни LM Studio не видно, показывать людям нельзя.

## 2а. Связка с маком (когда рабочая модель там)

```powershell
curl.exe -s http://192.168.1.50:1234/v1/models     # адрес мака: список моделей
```

Должны быть видны все три: чат-модель, vision-модель и модель эмбеддингов.
Дальше — что видит сама платформа:

```powershell
(Invoke-RestMethod http://127.0.0.1:3000/api/health).providers |
  Select-Object id, available, note
```

Ожидается: `lmstudio` — доступен (это мак), `ollama` — доступен (это слабая
местная LM Studio). Если `lmstudio` недоступен, а `ollama` доступен — адреса
перепутаны местами, и весь тяжёлый разбор пойдёт на слабую машину.

Проверить, что менеджер моделей молчит (guard `REMOTE_LM` применён): в
`logs\server.log` при прогоне **не должно** быть строк `[model-manager]` о
загрузке и выгрузке. Если они есть — сервер трогает модели не на той машине.

## 3. Вход и данные на месте

Открыть `http://localhost:3000`, войти под своей учётной записью из `users.json`.

- вход проходит → `users.json` перенесён и читается;
- в списке видны прошлые сессии → `data\app.db` перенесена целиком (вместе с
  `-wal` и `-shm`), а не обрезана на копировании;
- открывается прошлый результат, файлы скачиваются → `data\outputs`, `data\archive` на месте.

База знаний — отдельно, её индекс лежит в той же `app.db`:

```powershell
(Invoke-RestMethod http://127.0.0.1:3000/api/health).kb
```

Ожидается `enabled: true` и порядка 12,5 тыс. чанков, из них с векторами —
столько же. Ноль чанков при непустом `KB_DIR` означает, что кто-то запускал
`kb:index` при недоступной папке: переиндексация сначала чистит таблицу и только
потом читает диск. Лечится восстановлением `data\` из копии.

## 4. Настоящий прогон

Новая сессия → загрузить `ГПЗУ.pdf` и `МСК-47_Горбунки.dwg` → запустить анализ.

Что доказывает каждый этап:

| Этап | Что подтверждает |
|---|---|
| распознавание страниц скана | poppler (`pdfinfo`, `pdftoppm`) + vision-модель |
| выжимка по DWG (слои, габариты, надписи) | LibreDWG (`dwg2dxf`) |
| ответ модели по существу, а не «обращения кончились» | окно контекста подобрано под эту машину |
| ссылки на пункты СП/ГОСТ в отчёте | `KB_DIR` указывает на перенесённую базу знаний |
| план участка рисуется, зоны видны | геометрический движок и worker_threads |
| выгрузка комплекта (PDF + PNG) | Chromium Playwright установлен |
| выгрузка чертежа | DXF всегда; DWG — от конвертера, с пометкой «(конвертер)» |

В журнале смотреть `logs\server.log` — там же видно, какая модель загружалась и
с каким контекстом.

## 5. Внешний доступ

```powershell
Select-String -Path logs\tunnel.log -Pattern "Registered tunnel connection" | Select-Object -Last 4
curl.exe -s "https://dns.google/resolve?name=enso-nexus.com&type=A"
```

Соединения зарегистрированы (обычно четыре), DoH отдаёт адреса Cloudflare
(`104.21.*` / `172.67.*`).

**Главная проверка — с чужой сети.** С телефона по мобильному интернету открыть
<https://enso-nexus.com/api/health> — должно прийти `ok:true`. Проверять адрес
командами с самой машины бессмысленно: локальный резолвер и сертификат могут
быть подменены (в сети мака это делает FortiGate).

Error 1033 — коннекторов нет. 502 — туннель есть, сервера на :3000 нет.

## 6. Happ включён и Happ выключен

Один и тот же короткий список, дважды. Это и есть доказательство требования
«работает без Happ»:

| Проверка | Happ вкл | Happ выкл |
|---|---|---|
| `curl http://127.0.0.1:3000/api/health` | ok | **ok — обязательно** |
| локальная модель отвечает | да | **да — обязательно** |
| прогон анализа на локальной модели доходит до отчёта | да | **да — обязательно** |
| туннель зарегистрирован | да | зависит от сети (если её фильтр режет туннель — нет) |
| облачный провайдер отвечает | да | зависит от сети и региона |

Первые три строки при выключенном Happ обязаны быть «да». Если хоть одна
проваливается — где-то в конфигурации завёлся прокси или зависимость от
виртуального адаптера, и это надо снять (см. [2-СЕТЬ-И-HAPP.md](2-СЕТЬ-И-HAPP.md), п. 3).

## 7. Подбор контекста под видеокарту

Не «поставить как на маке», а замерить:

1. в LM Studio загрузить чат-модель с `LOCAL_AI_CONTEXT` из `.env`;
2. посмотреть занятость VRAM (диспетчер задач → Производительность → GPU,
   строка «Выделенная память»); если модель поехала в общую память — окно
   уменьшать вдвое и повторять;
3. прогнать анализ 17-страничного ГПЗУ и засечь время;
4. записать в отчёт: модель, окно, VRAM занято, время прогона.

Признак, что окно велико: prefill длится минутами, `LOCAL_AI_TIMEOUT` (600 с)
срабатывает, в интерфейсе — обрыв анализа.

## 8. Перезагрузка

Перезагрузить машину, ничего руками не запуская, подождать 3 минуты:

```powershell
curl.exe -s http://127.0.0.1:3000/api/health
```

Отвечает — автозапуск настроен. Нет — разобрать: служба `cloudflared`
(`Get-Service cloudflared`), задача планировщика (`schtasks /query /tn "Enso-nexus"`),
автовход в систему (LM Studio без сеанса пользователя не работает).

## 9. Мак выключен из работы

Туннель обязан быть поднят ровно на одной машине:

```bash
# на маке
bash scripts/serve-public.sh stop
```

Проверить, что после этого `https://enso-nexus.com` продолжает отвечать
(значит отвечает Windows), а в панели Cloudflare у туннеля `enso-nexus`
ровно один активный коннектор.

## Что писать в отчёте

По каждому пункту: команда, её вывод, вердикт. Отдельным списком — то, что не
заработало, с причиной и последствием («LibreDWG под Windows не собран → DWG на

записывается — «не проверялось», а не «работает».
