# 1. Перенос сервера на Windows — по шагам

## 0. Что переносим

Платформа — это один процесс Node (`server/index.js`), который слушает
`127.0.0.1:3000`, хранит всё в SQLite (`data/app.db`) и файлах внутри `data/`,
а наружу выходит через именной туннель Cloudflare (`cloudflared`). Никакой
базы данных отдельным сервисом, никакого веб-сервера перед ним, никакой сборки
фронтенда — `public/` отдаётся тем же процессом.

Значит перенос состоит ровно из четырёх вещей:

1. код — `git clone` (репозиторий `Ni1-1a/ENSO-Nexus`, его корень — эта папка `Web`);
2. данные и секреты — `.env`, `users.json`, `data/` — вручную, их в git нет;
3. внешние программы, которые сервер вызывает через `execFile`: poppler, LibreDWG,
   LM Studio (`lms`), Chromium для Playwright;
4. туннель — ключи `cloudflared` и `config.yml` с путями, переписанными под Windows.

Мак после переезда остаётся рабочим запасным вариантом: код тот же, данные те же.
Единственное, что нельзя, — держать туннель поднятым на обеих машинах сразу.

## 1. Требования к Windows-машине

**Система:** Windows 10 22H2 или Windows 11, x64. Права администратора нужны
для установки программ и службы туннеля; сам сервер администратора не требует.

**Диск:** ≥ 40 ГБ свободно. Разбивка: `data/` ≈ 213 МБ (растёт с каждым прогоном,
архив результатов не чистится), `Knowledge-Base` ≈ 673 МБ, `node_modules` ≈ 112 МБ,
Chromium Playwright ≈ 450 МБ, модели LM Studio — 20–40 ГБ.

> **Если рабочая модель остаётся на маке** (выбранный расклад — см.
> [5-СХЕМЫ-РАЗМЕЩЕНИЯ.md](5-СХЕМЫ-РАЗМЕЩЕНИЯ.md)), таблица про VRAM ниже к делу
> не относится: тяжёлые модели на этой машине не считаются. Требования к диску
> и к питанию остаются, требование к видеокарте — нет.

**Память и видеокарта — это про локальные модели.** На маке платформа работает
на `qwen/qwen3.5-35b-a3b` (20,6 ГБ весов) с контекстом 98 304 токена, и там
48 ГБ единой памяти, доступной видеоядру. На Windows память видеокарты отдельная,
и это главное ограничение:

| VRAM | Что реально | Что ставить в `.env` |
|---|---|---|
| 24 ГБ (4090, 3090) | `qwen3.5-35b-a3b` Q4 влезает по весам, но окно придётся урезать | `LOCAL_AI_CONTEXT=32768`, `LOCAL_AI_OCR_CONTEXT=16384` |
| 16 ГБ | модель поменьше (`qwen3-coder-30b` Q3/Q4 с выгрузкой части слоёв в CPU — медленно) | `LOCAL_AI_CONTEXT=16384`, `LOCAL_AI_MAX_TOKENS=8192` |
| 8–12 ГБ или нет дискретной видеокарты | локальные модели практически неприменимы к 17-страничным сканам | `AI_PROVIDER=auto` и работать на облачных моделях |

Выгрузка слоёв в оперативную память в LM Studio работает, но prefill длинного
промпта падает в разы; при `LOCAL_AI_TIMEOUT=600000` анализ будет упираться
в таймаут. Подбирать надо замером, а не на глаз, — см. [4-ЧЕКЛИСТ.md](4-ЧЕКЛИСТ.md), п. 7.

**Питание.** На маке от сна спасал `caffeinate -i` внутри `serve-public.sh`.
На Windows его аналога в скрипте нет — сон отключается один раз в системе:

```bat
powercfg /change standby-timeout-ac 0
powercfg /change hibernate-timeout-ac 0
powercfg /change disk-timeout-ac 0
```

Крышку ноутбука тоже надо развязать со сном: Панель управления → Электропитание →
«Действие при закрытии крышки» → «Действие не требуется» (от сети).

## 2. Программы, которые надо поставить

Всё, кроме LM Studio, ставится из PowerShell от администратора.

```powershell
winget install --id Microsoft.PowerShell        # PowerShell 7: скрипты win/scripts рассчитаны на него
winget install --id OpenJS.NodeJS.LTS           # Node 24 LTS или новее
winget install --id Git.Git
winget install --id Cloudflare.cloudflared
```

Проверка Node — она важнее версии в выводе `node -v`, потому что база лежит
на встроенном модуле `node:sqlite`, а он до Node 23.4 требовал флага:

```powershell
node -e "require('node:sqlite'); console.log('node:sqlite ok')"
```

Если команда ругается — поставить Node 24 LTS или новее и повторить.
`npm ci` компилятора не требует: нативных зависимостей в проекте нет.

**poppler** (`pdfinfo`, `pdftotext`, `pdftoppm` — ими разбираются PDF и режутся
страницы сканов для VLM-OCR). Готовых сборок в winget может не оказаться —
проверить `winget search poppler`, иначе взять архив с
<https://github.com/oschwartz10612/poppler-windows/releases>, распаковать
в `C:\Tools\poppler` и добавить `C:\Tools\poppler\Library\bin` в системный PATH.

**LibreDWG** (`dwg2dxf`, `dxf2dwg` — чтение DWG и запасная сборка DWG без AutoCAD).
Сборки для Windows — в релизах <https://github.com/LibreDWG/libredwg/releases>
(архив с `win64` в имени), распаковать в `C:\Tools\libredwg\bin`, добавить в PATH.
Если сборки не найдётся — платформа не падает: DWG на входе просто не читается,
а на выходе отдаётся DXF, и в примечаниях к результату это написано прямым текстом.

Проверка обоих наборов:

```powershell
pdfinfo -v ; pdftoppm -v ; dwg2dxf --version ; dxf2dwg --version
```

**LM Studio** — с <https://lmstudio.ai>, обычным установщиком. После установки
включить CLI (сервер управляет загрузкой моделей через него):

```powershell
& "$env:USERPROFILE\.lmstudio\bin\lms.exe" bootstrap
lms --version
```

В самой LM Studio: скачать чат-модель и vision-модель для OCR (на маке это
`qwen/qwen3.5-35b-a3b` и `qwen/qwen3-vl-8b`), включить локальный сервер на
порту 1234 и поставить автозапуск сервера при старте приложения.

**Chromium для Playwright** (растеризация SVG в PNG для отчётов) — ставится уже
внутри проекта, после `npm ci`:

```powershell
npx playwright install chromium
```

## 3. Что скопировать с мака

В git этого нет и не будет — переносить руками, на флешке или внешнем диске.
Скрипт `win/scripts/собрать-пакет-на-маке.sh` собирает всё это в один архив.

| Что | Откуда на маке | Размер | Обязательно |
|---|---|---|---|
| `.env` | `Pilot 1/Web/.env` | 9 КБ | да — в нём ключи API и все лимиты |
| `users.json` | `Pilot 1/Web/users.json` | 3 КБ | да — без него в платформу никто не войдёт |
| `data/` | `Pilot 1/Web/data/` | 213 МБ | да, если нужны прошлые сессии, прогоны и архив результатов |
| ключ туннеля | `~/.cloudflared/73ae7cf2-b2be-47f1-bfc3-80241846e71c.json` | 175 Б | да — без него туннель `enso-nexus` не поднять |
| сертификаты зон | `~/.cloudflared/cert.pem`, `cert-ru.pem` | 282 Б | только для команд `tunnel route dns`; для запуска не нужны |
| `config.yml` туннеля | `~/.cloudflared/config.yml` | 2 КБ | да (путь к ключу внутри придётся переписать) |
| база знаний | `ENSO-Nexus/Knowledge-Base/` | 673 МБ | **не срочно**: индекс уже внутри `data/app.db`, папка нужна только для переиндексации — см. [5-СХЕМЫ](5-СХЕМЫ-РАЗМЕЩЕНИЯ.md), п. 5 |
| база Гриши | `ENSO-Nexus/Knowledge-Base-Гриша/` | — | там же |
| исходные данные пилота | `ENSO-Nexus/Pilot 1/Исходные данные/` | 13 МБ | да — на них проверяется прогон (ГПЗУ.pdf, МСК-47_Горбунки.dwg) |

Чего **не** копировать: `node_modules/` (ставится заново — внутри есть бинарники
под macOS), `logs/`, `.DS_Store`, папку `Перезапуск/` (она с `.command`-файлами,
на Windows их место заняли `win/scripts/*.bat`).

**База копируется только при остановленном сервере.** SQLite в режиме WAL держит
рядом `app.db-wal` и `app.db-shm`; если скопировать `app.db` на ходу, часть
последних записей останется в WAL и потеряется. Порядок: остановить сервер →
скопировать все три файла вместе → запускать.

## 4. Установка на Windows

```powershell
# 1. Код (корень репозитория — это папка Web)
cd C:\
mkdir C:\Enso ; cd C:\Enso
git clone https://github.com/Ni1-1a/ENSO-Nexus.git web
cd C:\Enso\web

# 2. Данные и секреты из перенесённого архива
#    .env, users.json → в C:\Enso\web\
#    data\            → в C:\Enso\web\data\
#    Knowledge-Base   → туда, где она будет жить (этот путь пойдёт в KB_DIR).
#                       Не срочно: поиск работает от индекса в data\app.db

# 3. Зависимости
npm ci
npx playwright install chromium
```

Дальше — `.env`. Взять перенесённый файл и поправить в нём только пути и то,
что относится к машине; ключи API остаются как были:

```ini
LOCAL_AI_BASE_URL=http://192.168.1.50:1234/v1   # адрес мака: рабочая модель там
OLLAMA_BASE_URL=http://localhost:1234/v1        # слабая местная LM Studio, запасной путь
KB_DIR=D:\Базы\Knowledge-Base                   # фактический путь базы знаний
ACAD_ENABLED=0            # мост к AutoCAD работает только на macOS (см. 3-РАЗЛИЧИЯ)
LOCAL_AI_CONTEXT=32768    # как выставлено в LM Studio НА МАКЕ
LOCAL_AI_OCR_CONTEXT=16384
```

Полный шаблон со всеми переменными и пояснениями — [env.windows.example](env.windows.example).

Пути в `.env` пишутся с обратными слэшами и без кавычек. Кириллица в пути к
проекту допустима, но лишний повод для сюрпризов — `C:\Enso\web` спокойнее.

## 5. Правки в коде

Три места ищут внешние программы по путям Homebrew и на Windows их не находят.
Точные патчи с готовым кодом — в [3-РАЗЛИЧИЯ-MAC-WINDOWS.md](3-РАЗЛИЧИЯ-MAC-WINDOWS.md).
`doc-vision.js` и `cad.js` работают и так, если poppler и LibreDWG лежат в PATH.

Что обязательно — зависит от расклада:

- **модели на этой же машине** → патч поиска `lms.exe` в `model-manager.js`
  ([3-РАЗЛИЧИЯ](3-РАЗЛИЧИЯ-MAC-WINDOWS.md), п. 1);
- **рабочая модель на маке, LM Studio есть и здесь** → вместо него guard
  `REMOTE_LM` ([5-СХЕМЫ](5-СХЕМЫ-РАЗМЕЩЕНИЯ.md), п. 3): иначе сервер будет
  управлять моделями не на той машине.

## 6. Туннель

```powershell
# 1. Ключ и конфиг — в профиль пользователя
mkdir $env:USERPROFILE\.cloudflared
# скопировать 73ae7cf2-b2be-47f1-bfc3-80241846e71c.json, config.yml (и cert*.pem, если нужны)

# 2. В config.yml поправить ОДНУ строку — путь к ключу:
#    credentials-file: C:\Users\<имя>\.cloudflared\73ae7cf2-b2be-47f1-bfc3-80241846e71c.json
#    Блок ingress не трогать: все пять имён смотрят в http://localhost:3000

# 3. Проверить конфиг
cloudflared tunnel ingress validate
```

**Перед первым запуском остановить туннель на маке:**

```bash
cd "…/Pilot 1/Web" && bash scripts/serve-public.sh stop
```

Иначе у туннеля `enso-nexus` окажется два живых коннектора, и Cloudflare начнёт
раскидывать запросы между маком и Windows — человек будет попадать то в одну
базу, то в другую, без всякой закономерности.

В `config.yml` стоит `protocol: http2` — это след борьбы с FortiGate в сети мака,
где QUIC резался наглухо. На новой сети сначала попробовать без этой строки
(тогда идёт QUIC — он быстрее и стабильнее держит соединение); если туннель не
поднимается, вернуть `protocol: http2`. Подробности и что делать, если сеть режет
и это, — в [2-СЕТЬ-И-HAPP.md](2-СЕТЬ-И-HAPP.md).

## 7. Первый запуск

```powershell
cd C:\Enso\web
pwsh -File win\scripts\start.ps1
```

Скрипт делает то же, что `serve-public.sh` на маке: поднимает сервер, поднимает
туннель, ждёт в его логе `Registered tunnel connection`, запускает watchdog
(проверка раз в минуту, перезапуск после двух подряд неудачных). Останов —
`stop.ps1`, полный перезапуск — `restart.ps1`, те же три действия двойным
кликом — `.bat`-файлы рядом.

Проверка — [4-ЧЕКЛИСТ.md](4-ЧЕКЛИСТ.md). Минимум прямо сейчас:

```powershell
curl.exe -s http://127.0.0.1:3000/api/health
```

Должно прийти `{"ok":true,...}` с `"aiMode":"local"` (LM Studio поднят) или
`"live"` (работаем на облачной модели). `"mock"` означает, что ни ключа, ни
локального сервера не видно, — это заглушка, показывать её людям нельзя.

## 8. Автозапуск после перезагрузки

Два куска, и они ставятся по-разному.

**Туннель — службой Windows:**

```powershell
cloudflared service install
```

Служба читает конфиг не из вашего профиля, а из профиля SYSTEM
(`C:\Windows\System32\config\systemprofile\.cloudflared\`) — при установке файлы
туда копируются. Поэтому после любой правки `config.yml` в своём профиле службу
надо переустановить (`cloudflared service uninstall` → `install`) или скопировать
файлы туда руками. Если туннель поднимается службой, из `start.ps1` его запуск
надо выключить — параметр `-NoTunnel`.

**Сервер — задачей планировщика при входе в систему:**

```powershell
schtasks /create /tn "Enso-nexus" /sc onlogon /rl highest ^
  /tr "pwsh -NoProfile -WindowStyle Hidden -File C:\Enso\web\win\scripts\start.ps1 -NoTunnel"
```

Именно `onlogon`, а не `onstart`: LM Studio — обычное оконное приложение, без
сеанса пользователя оно не работает. Значит на машине нужен автоматический вход
(`netplwiz` → снять «Требовать ввод имени пользователя и пароля») и запрет
блокировки экрана со сном. Если локальные модели не используются, `onstart`
надёжнее — сервер поднимется до входа кого-либо.

## 9. Если что-то не поднялось

| Симптом | Причина | Что делать |
|---|---|---|
| `/api/health` не отвечает | сервер упал на старте | `logs\server.err.log` — первая же строка обычно всё объясняет |
| `"aiMode":"mock"` | LM Studio не поднят или порт другой | открыть LM Studio, включить сервер, проверить `curl http://localhost:1234/v1/models` |
| «CLI `lms` не найден» | не сделан `lms bootstrap` или не применён патч из 3-РАЗЛИЧИЯ | оба пункта проверить |
| снаружи Error 1033 | коннекторов нет: туннель не запустился | `logs\tunnel.log`, дальше [2-СЕТЬ-И-HAPP.md](2-СЕТЬ-И-HAPP.md) |
| снаружи 502 | туннель жив, сервер на :3000 — нет | поднять сервер; проверить, что он слушает именно `127.0.0.1:3000` |
| PDF не разбираются | нет poppler в PATH | `pdfinfo -v` в новом окне PowerShell (PATH подхватывается только новыми процессами) |
| DWG не читается | нет LibreDWG в PATH | `dwg2dxf --version`; без него на входе — только DXF |
| ответы приходят обрезанными | окно модели меньше промпта | уменьшить `LOCAL_AI_DOC_CHAR_LIMIT`, увеличить `LOCAL_AI_CONTEXT` в пределах VRAM |

## 10. Откат на мак

Мак ничего не теряет. Если Windows-машину надо вывести из игры:

1. на Windows: `pwsh -File win\scripts\stop.ps1` (и `cloudflared service uninstall`, если ставили службу);
2. скопировать обратно `data\` (сервер остановлен, все три файла базы);
3. на маке: `bash scripts/serve-public.sh`.

Адрес `https://enso-nexus.com` тот же, домен и DNS не трогаются вообще — меняется
только то, на какой машине живёт коннектор туннеля.
