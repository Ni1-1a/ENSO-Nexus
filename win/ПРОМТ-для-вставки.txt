ЧТО ЭТО ЗА ПРОЕКТ
Веб-приложение для анализа исходных данных и посадки здания на земельный участок
(ГПЗУ, ПЗЗ, охранные зоны, DWG). Node + Express 5, CommonJS, база — встроенный
node:sqlite, фронтенд без сборки. Один процесс слушает 127.0.0.1:3000 и отдаёт и API,
и статику. Наружу выходит через именной туннель Cloudflare (enso-nexus). Репозиторий
https://github.com/Ni1-1a/ENSO-Nexus.git — его корень и есть корень приложения.
В корне лежит CLAUDE.md с правилами проекта: прочитай, они действуют и здесь.
Если рядом есть папка win/ — там подробные документы по этому переносу (1-ПЕРЕНОС,
2-СЕТЬ-И-HAPP, 3-РАЗЛИЧИЯ-MAC-WINDOWS, 4-ЧЕКЛИСТ, 5-СХЕМЫ-РАЗМЕЩЕНИЯ, env.windows.example
и скрипты win/scripts). Прочитай их до первой команды. Если папки нет — всё нужное
есть в этом сообщении.

РАСКЛАД ПО МАШИНАМ — он выбран, другой не предлагай
  Эта Windows-машина: сервер, база data\, туннель наружу. Машина СЛАБАЯ.
  LM Studio на ней стоит, но только с небольшой моделью.
  Мак: рабочая модель qwen/qwen3.5-35b-a3b, vision-модель qwen/qwen3-vl-8b для сканов
  и модель эмбеддингов. Сервер ходит к ним по локальной сети.
  База знаний лежит отдельной папкой, путь задаётся в KB_DIR.
  Мост AutoCAD не работает (он на AppleScript и только на macOS) — ACAD_ENABLED=0.

ЧЕГО НА ЭТОЙ МАШИНЕ НЕТ И БЫТЬ НЕ ДОЛЖНО В GIT
.env, users.json, data\ — переносятся с мака вручную. В .env ключи API, в users.json
ФИО и адреса людей платформы. Не коммить их, не выводить в чат, из .gitignore не убирать.
Проверь, что они на месте; чего нет — скажи прямо, что именно и что из-за этого
не заработает. Не изображай успех.

ПОРЯДОК РАБОТЫ

1. ОКРУЖЕНИЕ. Проверь и доустанови:
     winget install --id Microsoft.PowerShell     (скрипты рассчитаны на PowerShell 7)
     winget install --id OpenJS.NodeJS.LTS        (нужен Node 24 LTS или новее)
     winget install --id Git.Git
     winget install --id Cloudflare.cloudflared
   Версия Node важна не сама по себе, а вот этим:
     node -e "require('node:sqlite'); console.log('ok')"
   Ругается — ставь Node 24+. Компилятор не нужен, нативных зависимостей в проекте нет.
   Внешние программы, которые сервер вызывает через execFile, должны быть в PATH:
     pdfinfo, pdftotext, pdftoppm   — poppler, сборки для Windows:
                                      github.com/oschwartz10612/poppler-windows/releases
     dwg2dxf, dxf2dwg               — LibreDWG: github.com/LibreDWG/libredwg/releases (win64)
   Без poppler не читаются PDF и не режутся страницы сканов. Без LibreDWG не читается
   DWG на входе, а на выходе вместо DWG уходит DXF — платформа об этом честно пишет.
   PATH подхватывается только новыми процессами: после правки открой окно заново.

2. ЗАВИСИМОСТИ И ТЕСТЫ.
     npm ci

3. ОБЯЗАТЕЛЬНАЯ ПРАВКА КОДА — одна.
   server/services/model-manager.js управляет моделями через ЛОКАЛЬНЫЙ CLI `lms`:
   грузит с нужным контекстом, выгружает соседа, считает бюджет памяти от os.totalmem().
   По сети он не работает. Раз LM Studio стоит и здесь, без правки сервер будет грузить
   и выгружать модели на этой слабой машине, пока запросы уходят на мак, а в пикере
   рабочая 35B отметится как «не помещается» — бюджет посчитан по оперативке Windows.
   Добавь сразу после LMS_CANDIDATES:

     /*
      * Управлять моделями можно только там, где они работают. Если LM Studio вынесена
      * на другую машину (LOCAL_AI_BASE_URL смотрит не в петлю), локальный CLI управлял
      * бы ЧУЖОЙ, не той LM Studio. В таком случае менеджер обязан молчать — загрузку
      * берёт на себя сама LM Studio (JIT), а контекст задаётся в её настройках.
      */
     const REMOTE_LM = !/^https?:\/\/(localhost|127\.0\.0\.1|\[::1\])(:|\/)/i
       .test(config.localAiBaseUrl);

   и первой строкой в findLms():   if (REMOTE_LM) return null;

   Больше ничего «под Windows» не переписывай: мак остаётся рабочей запасной машиной,
   код должен работать на обеих. doc-vision.js и cad.js ищут программы по путям Homebrew,
   но последним кандидатом берут просто имя из PATH — на Windows этого достаточно.

4. .env. Возьми перенесённый с мака файл и поправь только машинное; ключи API не трогай:

     AI_PROVIDER=local
     LOCAL_AI_BASE_URL=http://<IP-МАКА>:1234/v1
     LOCAL_AI_MODEL=qwen/qwen3.5-35b-a3b
     LOCAL_AI_OCR_MODEL=qwen/qwen3-vl-8b
     LOCAL_AI_CONTEXT=32768
     LOCAL_AI_OCR_CONTEXT=16384
     LOCAL_AI_TIMEOUT=600000
     OLLAMA_BASE_URL=http://localhost:1234/v1
     KB_DIR=<ПУТЬ-К-БАЗЕ-ЗНАНИЙ>
     ACAD_ENABLED=0
     BIND_HOST=127.0.0.1
     PORT=3000

   Почему именно так:
   • К LOCAL_AI_BASE_URL жёстко привязаны не только чат и анализ, но и распознавание
     сканов (doc-vision.js) и эмбеддинги базы знаний (kb.js). Поэтому там мак, и все три
     модели обязаны быть на маке.
   • Контексты 32768/16384 занижены против мачных 98304/65536 намеренно: после правки
     из п. 3 выгружать соседа больше некому, и чат-модель, vision и эмбеддинги должны
     помещаться на маке ОДНОВРЕМЕННО. Значения обязаны совпадать с тем, что выставлено
     в LM Studio на маке.
   • OLLAMA_BASE_URL — это отдельный OpenAI-совместимый слот. Местная LM Studio появится
     в пикере вторым провайдером (подписан «Ollama (локально)») как запасной путь, когда
     мак выключен. Зрения и эмбеддингов у слота по реестру нет — только текст.

5. БАЗА ЗНАНИЙ. Индекс (12,5 тыс. чанков с эмбеддингами) лежит в таблице kb_chunks
   внутри data\app.db, поиск читает только её. Значит поиск работает сразу после
   переноса data\, даже если самой папки ещё нет. Три правила:
   • KB_DIR обязана быть НЕПУСТОЙ — из неё собирается список баз; пустая = базы знаний
     в интерфейсе нет вообще, даже при полном индексе.
   • НЕ запускай npm run kb:index, пока не убедился, что папка доступна: reindex()
     сначала делает DELETE FROM kb_chunks и только потом читает диск. Отвалившийся
     сетевой диск = уничтоженный индекс.
   • Если папка сетевая (лежит на маке) — путь писать UNC-именем (\\MAC\Knowledge-Base),
     а не буквой подключённого диска: буквы не видны службе и задаче планировщика.

6. ТУННЕЛЬ.
   • Скопированные с мака config.yml и ключ <id>.json положить в %USERPROFILE%\.cloudflared
   • В config.yml переписать credentials-file на путь Windows. Блок ingress не трогать:
     все пять имён смотрят в http://localhost:3000
   • cloudflared tunnel ingress validate
   • ПЕРЕД запуском убедись, что туннель на маке остановлен. Два живых коннектора
     у одного туннеля означают, что Cloudflare раскидывает людей между маком и этой
     машиной случайным образом — и они попадают в разные базы. Если остановить мак
     нельзя, скажи мне и не запускай.
   • В config.yml стоит protocol: http2 — это след борьбы с FortiGate в сети мака.
     На новой сети сначала попробуй без этой строки (пойдёт QUIC, он быстрее); не
     поднимется — верни http2.

10. HAPP — ОТДЕЛЬНОЕ ТРЕБОВАНИЕ, НЕ ПОЖЕЛАНИЕ.
   Интернет на этой машине идёт через Happ (клиент Xray). Платформа обязана работать
   и при выключенном Happ. Значит:
   • никаких HTTP_PROXY/HTTPS_PROXY в .env, в переменных службы и в задаче планировщика;
   • никаких адресов Happ в config.yml туннеля — там только http://localhost:3000;
   • автозапуск платформы не зависит от автозапуска Happ.
   Учти: Node системный прокси НЕ читает — ни fetch, ни Anthropic SDK, ни @google/genai.
   Поэтому у Happ предпочтителен режим TUN/VPN: он перехватывает трафик прозрачно и не
   требует ни строчки в коде. Режим системного прокси облачные модели не спасёт, запросы
   пойдут мимо; туннель в SOCKS увести тоже нельзя.
   Прогони проверки ДВАЖДЫ — с включённым Happ и с выключенным — и покажи таблицей:
     сервер на 127.0.0.1:3000 .............. обязан работать в обоих состояниях
     модель на маке отвечает ............... обязана в обоих (это локальная сеть)
     прогон анализа доходит до отчёта ...... обязан в обоих
     туннель зарегистрирован ............... может отвалиться без Happ, это допустимо
     облачный провайдер отвечает ........... может отвалиться без Happ, это допустимо

11. ВНЕШНИЙ АДРЕС. Проверять только СНАРУЖИ: локальный резолвер и сертификат могут быть
   подменены (в сети мака этим занимается FortiGate — живой домен выглядел парковкой).

12. АВТОЗАПУСК И ПИТАНИЕ.
     powercfg /change standby-timeout-ac 0
     powercfg /change hibernate-timeout-ac 0
     cloudflared service install
     schtasks /create /tn "Enso-nexus" /sc onlogon /rl highest ^
