# Промт для Claude Code на Windows

Готовый текст — в [ПРОМТ-для-вставки.txt](ПРОМТ-для-вставки.txt): открыть, выделить
всё, скопировать, вставить одним сообщением.

## Перед вставкой заполнить три места

В шапке промта стоят угловые скобки — подставьте свои значения, иначе Claude
остановится и переспросит:

| Что | Где взять |
|---|---|
| `<IP-МАКА>` | на маке: `ipconfig getifaddr en0` (и закрепить адрес в роутере) |
| `<ПУТЬ-К-БАЗЕ-ЗНАНИЙ>` | куда ляжет `Knowledge-Base`; если останется на маке — UNC-путь `\\MAC\Knowledge-Base` |
| `C:\Enso\web` | папка проекта, если решите класть в другое место |

## Что должно быть сделано до вставки

1. Claude Code открыт **в папке проекта**, а не в домашней.
2. Разложен перенесённый с мака пакет: `.env`, `users.json`, `data\`, ключи
   `.cloudflared`. Без них Claude дойдёт до середины и упрётся — ключи и данные
   людей взять неоткуда.
3. **Туннель на маке остановлен**: `bash scripts/serve-public.sh stop`.
4. На маке в LM Studio включён «Serve on Local Network», загружены три модели
   (чат, vision, эмбеддинги) с контекстами 32768 / 16384, порт 1234 открыт
   в брандмауэре. Это делает владелец: промт прямо запрещает Claude чинить мак
   удалённо — он только скажет, чего не хватает.

Если папка `win/` на Windows-машине не окажется (репозиторий не запушен), промт
всё равно рабочий: все существенные детали — правка `model-manager.js`, состав
`.env`, порядок с туннелем, проверки — записаны в нём самом.

## Что промт заставляет сделать

Проверить окружение и доустановить недостающее → `npm ci` + Chromium + тесты →
внести guard `REMOTE_LM` в `model-manager.js` → собрать `.env` под расклад
«модель на маке» → перенести туннель → запустить → проверить связку с маком →
прогнать настоящий анализ на ГПЗУ и DWG пилота → доказать таблицей, что всё
работает и с Happ, и без него → настроить автозапуск и проверить перезагрузкой.

## Почему промт написан именно так

- **Расклад задан жёстко.** Иначе модель начнёт «настраивать Windows вообще»
  и предложит IIS, Docker и nginx, которых здесь нет.
- **Правка кода ровно одна, и запрещено расширять.** Мак остаётся запасной
  машиной, код должен работать на обеих.
- **Сказано, что PowerShell-скрипты не запускались на Windows** — иначе их
  ошибки будут выглядеть как ошибки платформы.
- **Happ вынесен отдельным пунктом с двойной проверкой.** «Работает без Happ» —
  условие приёмки, а не пожелание.
- **Запрет на «сделано» без вывода команд** — правило проекта: подтверждение это
  прогон на настоящих данных и живых моделях.

## Короткий промт, когда всё уже поднято и нужно просто запустить

```
Подними Enso-nexus на этой Windows-машине. Читай win/5-СХЕМЫ-РАЗМЕЩЕНИЯ.md и win/4-ЧЕКЛИСТ.md.
Порядок: npm ci → pwsh -File win\scripts\start.ps1 → pwsh -File win\scripts\health.ps1.
Проверь /api/health (режим mock недопустим), что провайдер lmstudio указывает на мак,
туннель в logs\tunnel.log и внешний адрес снаружи. Не поднимай туннель, если он поднят
на маке. Что не работает — почини и покажи команды с выводом. Отвечай по-русски.
```
