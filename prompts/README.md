# Промты платформы

Здесь лежат ВСЕ тексты, которые уходят модели как задание. В коде их больше нет:
`server/services/prompts.js` читает файл по имени, а вызывающий код только выбирает,
какой именно.

**В файле лежит только текст промта.** Никаких заголовков и пояснений внутри —
они уехали бы модели вместе с остальным. Всё, что нужно сказать человеку, сказано
здесь, в этой таблице.

Правку подхватывает следующий прогон: файл перечитывается, когда изменились время
правки и размер, перезапуск сервера не нужен. Промт, который не читается или пуст,
останавливает работу с внятной ошибкой — молчаливого «модель работала без промта»
не бывает.

## Единая структура

С 08.09.2026 все промты-роли написаны по единой структуре из семи блоков, всегда
в этом порядке: РОЛЬ · ЗАДАЧА · ВХОД · ПРАВИЛА ЧЕСТНОСТИ · ПОРЯДОК РАБОТЫ ·
ФОРМАТ ОТВЕТА · ПРОВЕРЬ ПЕРЕД ОТВЕТОМ. Задания в `tasks/` — три блока:
ЗАДАЧА · УСЛОВИЯ · ОТВЕТ. Блок «Правила честности» дословно один и тот же во всех
промтах, предметные правила добавляются с номера 6. Подстановки `{{…}}` и имена
блоков `<…>` — контракт с кодом: не переименовывать. Критичное выделяется
ЗАГЛАВНЫМИ (полужирный может потеряться при сборке запроса). Обоснование каждой
правки — в документе «Промты Enso-nexus — сравнительная таблица и глоссарий (v3)».

## Задания (`tasks/`)

Это не «роль», а текст задачи в реплике пользователя — то, что модель читает последним.

| Файл | Когда уходит модели |
|---|---|
| `tasks/analysis-run.md` | Задание обычного прогона анализа |
| `tasks/compare-run.md` | Задание при сравнении нескольких моделей на одних данных |
| `tasks/restriction-match.md` | Основное задание извлечения ограничений (дальше код дописывает перечень слоёв и пожарный блок) |
| `tasks/restriction-no-fulltext.md` | Повтор, когда полные тексты документов не поместились в контекст |
| `tasks/restriction-empty-retry.md` | Повтор, когда модель вернула пустой список вопреки формулировкам в документах. Подстановка `{{hints}}` — найденные формулировки |
| `tasks/parcel-find-table.md` | Задание найти и перенести таблицу координат |
| `tasks/json-only.md` | Добавка к system для моделей, не принимающих `json_schema` |
| `tasks/adversary-revise.md` | Задание на доработку ответа по замечаниям проверяющего — дописывается в тот же диалог после черновика (чат, вопрос по области). Подстановка `{{issues}}` — пронумерованные замечания |

## Чего здесь нет

- **Порядок работы (шаги 0…13)** — это не промт, а данные: `server/services/workplan.js`,
  человек правит его в настройках и может загрузить свой xlsx. В промт он уходит
  отдельным блоком `<workplan>`.
- **Блоки контекста** (`<knowledge_base>`, `<session_state>`, `<site_inventory>`,
  выжимки документов) собираются из данных сессии — `claude/memory.js` и вызывающие сервисы.

## Как править

1. Открыть файл, поправить текст, сохранить.
2. Прогнать анализ — правка уже действует.
3. Если менялся смысл `system-prompt.md`, поднять `promptVersion` в `server/config.js`:
   он пишется в сессию и в выходные файлы, по нему потом видно, каким промтом сделан отчёт.
